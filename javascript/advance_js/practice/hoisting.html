🔄 JavaScript Hoisting

📌 What is Hoisting?

Definition: Hoisting is JavaScript's default behavior of moving declarations to the top of the current scope (function or global). Only declarations are hoisted, not initializations.

Let's see this in action 👇


console.log(a); // undefined
var a = 5;

Why? Because behind the scenes, JS rewrites it like this:


var a;
console.log(a); // undefined
a = 5;

📦 var vs let/const

var is hoisted and initialized as undefined, but let and const are hoisted differently.


console.log(x);  // ❌ ReferenceError
let x = 10;

Why? Because let and const are hoisted but stay in the "Temporal Dead Zone" (TDZ) until they are declared.

🧠 Function Hoisting

Function Declarations are hoisted completely (name + body), so you can call them before they're declared.


sayHello(); // ✅ Works

function sayHello() {
  console.log("Hello!");
}

Function Expressions (especially with const or let) are not hoisted:


sayHi(); // ❌ TypeError

const sayHi = function() {
  console.log("Hi!");
};

✅ Summary

  • var: Hoisted & initialized as undefined
  • let / const: Hoisted but not initialized — stay in TDZ
  • Function declarations: Fully hoisted
  • Function expressions: Not hoisted

🧪 Try It Yourself

Open DevTools (F12) > Console and experiment with the examples above. Try calling a function or accessing a variable before it's defined!
